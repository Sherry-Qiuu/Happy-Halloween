# 数据与隐私边界

> 决策日期：2026-11-04。**已变更**：早期版本主张"对话原文不落库"，现在**明确采集原文**，用于理解用户语言与偏好。
> 这个变更不是小事——原文是最敏感的一类数据，下面把它带来的义务写清楚。

## 1 采什么

| 数据 | 形态 | 位置 | 保留 | 用途 |
| --- | --- | --- | --- | --- |
| 应用状态（待办/目标/日历/反思） | gzip JSONL，每次保存一份 | `<data>/snapshots/<uid>/<day>.gz` | 90 天 | 画像、评测、反例集 |
| 对话原文 | 每轮 user/assistant 文本 | `<data>/conversations/<uid>/<day>.jsonl` | 90 天 | 语言偏好、错误分析 |
| 画像 | JSON（指标/槽位/姿态/风格） | `<data>/<uid>.profile.json` | 随账号 | 排布参数 |
| 长期记忆摘要 | JSON | `<data>/<uid>.memory.json` | 随账号 | 跨会话上下文 |
| 反馈 | 计数 + 最近 40 条 | profile 内 | 随账号 | 采纳率 |

## 2 原文采集的四条义务

既然要存原文，下面四条就必须同时成立，否则不要存：

**① 告知与同意**
注册页必须有明确勾选（默认不勾）：
> 为了记住你的习惯、把计划排得更准，我们会保存你的对话内容与日程记录；你可以随时导出或删除。

不做默认勾选——默认勾选在多数司法辖区不算有效同意。

**② 最小化与脱敏**
入库前对原文做一遍替换：手机号、邮箱、身份证、银行卡、详细地址 → `[手机号]` 等占位符。
只保留理解偏好必需的部分；用户粘贴的大段文本（>2000 字）截断并标记。

**③ 保留期与删除**
- 原文与快照统一 90 天，到期自动清理（启动时 prune）
- **账号删除 → 全部级联删除**（state、快照、原文、画像、记忆、会话）
- 用户请求删除某段对话 → 按 `conversation_id` 删除，且进入 30 天冷却（不再采集同类）

**④ 访问与用途**
- 原文只用于：画像、评测、错误复盘。**不用于**训练第三方模型、不对外提供
- 内部访问留审计日志（谁、何时、导出了谁的数据）
- 导出与删除接口必须存在，且是自助的

## 3 不允许采集的

| 类别 | 原因 |
| --- | --- |
| 健康、宗教、政治倾向、性取向 | 禁推断清单，且无排布价值 |
| 精确位置（粗于城市不需要） | 与功能无关 |
| 通讯录、相册等外部数据 | 超出授权范围 |
| 密码、验证码 | 任何情况下不落库 |
