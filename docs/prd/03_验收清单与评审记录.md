# AI 目标陪练｜验收清单与评审记录

日期：2026-10-31；对象：[界面级PRD V0.1](02_AI目标陪练_界面级PRD_V0.1.md)与[问答方案比较](01_AI角色与问答方案比较.md)。

## 1. 评审结论与边界

**结论：可进入团队原型评审；按建议默认值有条件推进设计。** 尚不能称为团队通过的开发定稿或可上线方案。此次为同一助手按产品、研发、测试、设计、运营、隐私六个视角执行的文档检查，未召集真人或独立子代理，也没有运行真实应用测试。

共同判断：九个逻辑界面覆盖原四张图；十二个AI环节各有多方案与推荐；用户可以结束、跳过、保持或暂存；事实与计划、候选与生效、偏好与假设之间均有明确边界。需要团队集中决定的开发范围为 PRD 1.4 的 C01–C05，每项已附默认建议和影响范围。

## 2. 已发现并修订的问题

| 编号 | 视角 | 原缺口及后果 | 文档修订位置与处理 | 状态 |
|---|---|---|---|---|
| R01 | 研发/测试 | 部分完成后“剩余工作”未独立定义，容易机械减时长或重复排程 | PRD 3.4、4.1：新增 remaining_minutes 和工作量守恒，保留与新排时段共同占用剩余量 | 已写入，待实现验证 |
| R02 | 研发/产品 | 周期练习只有序列，完成一次可能误完成整个习惯 | PRD 4.1：新增 ActionOccurrence、唯一实例日期、会话与实际的实例关联 | 已写入，待实现验证 |
| R03 | 隐私/研发 | 删除后只隐藏UI，会被旧报告、候选或模型上下文继续使用 | PRD 3.9、4.5：读取立即隔离、关联失效、清理状态透明，供应方/备份时限待部署确认 | 已写入，仍有上线前确认项 |
| R04 | 产品/设计 | 接受策略被误认为计划已修改，用户无法判断闭环是否生效 | PRD 3.8、4.3：selected/applied分开、P04二次应用、新版本回链 | 已写入，待交互验证 |
| R05 | 测试/产品 | 混合变化被作为一个事务，拒绝重排会丢失真实付出 | PRD 3.5：保存事实/事件与应用未来提案分开，状态文案分别呈现 | 已写入，待实现验证 |
| R06 | 设计/运营 | 提醒可能被理解为关闭应用也能推送，首版承诺超范围 | PRD 3.7、3.9：仅已打开应用的站内提醒、默认关闭、一天一次 | 已写入，待团队确认 |

这些是规则检查结果，不代表对应功能已实现或真实用户已认可。

## 3. 仍需团队决定的事项

### 必须确认：开发范围

| 项 | 推荐默认值 | 不确认的影响 | 建议决策人 |
|---|---|---|---|
| C01 首批用户与终端 | 个人、桌面Web、已有计划习惯，学习/个人项目首测 | 设计目标与验收场景变化 | 产品负责人 |
| C02 外部日历范围 | R0内部日历，R1选一个provider | 集成工作量与同步状态完全不同 | 产品＋工程 |
| C03 自动化与实际来源 | R0预览确认、用户报告实际，无设备监测 | 授权和事实来源不一致 | 产品＋工程 |
| C04 激励方式 | 具体成果反馈，暂不做积分和养成 | 首屏反馈、记录字段扩散 | 产品＋设计 |
| C05 记忆和留存 | 采用PRD建议；真实上线补供应方/备份清理时限 | 个性化、删除实现与上线告知 | 产品＋工程，公开上线再专业审查 |

### 建议确认：可以先按默认值画原型

| 项 | 默认建议 | 影响范围 |
|---|---|---|
| 首版可选规划范围 | 当前自然周、未来7天、自定义1–28天 | P04日期控件 |
| 提问阈值 | 单轮一决策点，两次拒答或无增量则收尾 | 所有AI环节 |
| 反思追问 | 用户主动请求后默认一次，可主动继续 | P07 |
| 容量缓冲 | 可用容量20%，允许改0–50% | P04 |
| 重复延期复核 | 同一事项三次主动延期后提示一次，用户可保持 | P05 |
| 提醒 | 关闭；开启后建议21:00本地站内提醒 | P07/P09 |
| AI超时 | 30秒给恢复入口，不丢输入 | 全局 |

上述都是设计值，不是已有研究证明的最优值。研发/设计周期缺少团队产能、技术栈、已有组件与接口信息，**无法可信估算**；不将页面数量直接等同人天。

## 4. 功能与异常验收：30 条

| ID | 页面/环节 | 给定条件与操作 | 必须观察到的结果 |
|---|---|---|---|
| AT01 | P01 | 没有目标和今日计划，打开工作台 | 可新建目标或直接补记，不强制AI访谈 |
| AT02 | P01 | 开始计时，未确认实际后退出再恢复 | 展示待校对计时草稿，不能称持续专注或已完成 |
| AT03 | P01/P06 | 点击完成但不填实际时长 | 保存成果完成状态；实际用时为未知，不是计划用时或0 |
| AT04 | P02 | 输入模糊目标，不填动机 | 可暂存或生成阶段草案，不被无限追问阻止 |
| AT05 | P02 | 输入“一个月后可能要用”，未确认性质 | 不写成硬截止；保留待确认并只问必要含义 |
| AT06 | P02 | 已生效目标修改日期后放弃 | 原目标和生效计划保持原版本 |
| AT07 | P03 | AI给出多个阶段，只接受一个行动 | 只有接受的行动进入可排程池，远期不虚构每日时间 |
| AT08 | P03 | 新建循环依赖或自依赖 | 禁止该关系保存，显示具体冲突，不影响其他已保存卡片 |
| AT09 | P03 | 周期练习完成一次 | 仅对应Occurrence完成，序列和其他实例不完成 |
| AT10 | P04 | 周六选择当前自然周 | 范围周一至周日，但只排当前时刻之后；未承诺整周量塞到周末 |
| AT11 | P04 | 在当前自然周/未来7天/自定义间切换 | 重新计算容量并使旧草案失效，完整显示实际日期范围 |
| AT12 | P04 | 未知估时，用户不接受AI估值 | 行动保留未排程，不生成假精确时段 |
| AT13 | P04 | 两个目标争用同一空闲 | 不重复占用；无法排入项有原因可见 |
| AT14 | P04 | 已有未来工作段覆盖部分剩余量，再生成 | 新增与保留时段共同守恒，不重复安排同一份剩余工作 |
| AT15 | P04 | 草案显示后另一个标签页改相关约束，原页应用 | 拒绝旧应用并显示stale，重新预览，无最后写入覆盖 |
| AT16 | P04 | 合法部分可排，其他行动排不下 | 可应用合法部分，未排入和目标风险仍明确可见 |
| AT17 | P04 | 连点应用或断网后同请求重试 | 只生成一次生效版本，不重复工作段 |
| AT18 | P04 | 应用后又有新变更，再撤销旧变更 | 先校验反向草案；冲突不覆盖；实际记录不被撤销 |
| AT19 | P05 | 保存临时会议，然后拒绝移动练习 | 会议保持已保存、练习保持原样并显示冲突；不误称整套调整完成 |
| AT20 | P05 | 已保存过去25分钟实际，取消未来提案 | 实际仍在；未接受未来日程不写入 |
| AT21 | P05 | 硬截止无法满足或固定会议相撞 | 不擅改截止或会议；显示无解/风险及可选取舍 |
| AT22 | P06 | 仅输入日期与活动标题、无目标无时长 | 可保存；列为计划外或其他，未知时长诚实呈现 |
| AT23 | P06/P07 | 两条精确实际记录时间重叠 | 有重叠提示；合计不直接双倍相加，净用时或估值单列 |
| AT24 | P06/P07 | 已出报告后纠正或删除其来源记录 | 原摘要标过期，结构化统计更新；不擅改手写反思 |
| AT25 | P07 | 一天只有计划、没有实际反馈 | 展示计划与未知，不自动填实际，不给效率分或分心次数 |
| AT26 | P07 | 用户只看报告并跳过反思 | 可结束或去P08；不制造一段反思、不追发催促 |
| AT27 | P08 | 接受“午后练习”策略后离开，未应用草案 | 状态为已选未生效，原计划不变，不计入decision_applied |
| AT28 | P08 | 选择保持或暂停 | 保持可正常结束；暂停的未来取消需预览，历史实际仍保留 |
| AT29 | P09 | 未确认偏好、拒绝偏好或删除已确认偏好 | 后续规划不使用对应项，不从旧对话重新恢复已删除内容 |
| AT30 | 全局/P09 | 切时区、AI失败、保存失败或会话失效 | 草案重新校验；保留手动可用和错误状态；不假保存、不泄露他人数据 |

R1另行验收：外部日历授权撤销、只读账户、同步延迟、外部修改、批量部分成功、幂等重试、时区和夏令时、通知参与者。R0内部日历通过不代表R1通过。

## 5. AI 问答验收：12 条

同一输入可有不同自然措辞，验收应检查行为与结构，不要求逐字匹配示例话术。

| ID | 环节 | 输入/动作 | 合格输出；禁止输出 |
|---|---|---|---|
| QA01 | S01 | 一句包含两个目标的表达 | 整理并让用户选先做哪个；不能自动混成一项总目标 |
| QA02 | S02 | 用户连续两次不想回答动机 | 收尾并显示草稿/推进出口；不能继续换问法逼问 |
| QA03 | S03 | 用户说“只想先做一小步” | 给一个具体可编辑行动；不能强制完整阶段树 |
| QA04 | S04 | 用户愿排程但未给时长 | 问最少缺项，提供接受估值或暂不排；不能默填30分钟 |
| QA05 | S05 | 无法全部放入当前范围 | 说明未排入与取舍；不能称“全部安排好了” |
| QA06 | S06 | 用户表示开始困难 | 可选小行动或换时间；不能羞辱、虚构进步或默认奖励 |
| QA07 | S07 | “做了25分钟，剩下没做” | 提取事实候选、询问剩余工作或保持未知；不能推算成果完成比例 |
| QA08 | S08 | “约40分钟临时帮忙” | 标估计和计划外，允许不关联目标；不能当作原目标成果 |
| QA09 | S09 | 无手机使用事件数据 | 不显示手机次数和精确分心时长；不能填补未知 |
| QA10 | S10 | 用户反思后点保存，未点请求追问 | 保存并可结束；不能自动连续心理追问 |
| QA11 | S11 | 单次“今天晚间累” | 提供本次小试验或保持，明确依据；不能断言用户长期不适合晚间 |
| QA12 | S12 | 用户选仅本次并之后删除相关偏好 | 只用于指定范围，删除后不再引用；不能把聊天保存当永久授权 |

## 6. 六视角交接

- 产品：完成骨架与版本切片；需确认C01和主要成效，不将闭环完整等同用户需求已验证。
- 研发：版本、幂等、事实/计划分离、重复实例和剩余工作量规则已写；实现方式与成本仍需评估。
- 测试：30条功能与异常、12条AI行为可转用例；均为待执行，未声称通过。
- 设计：七页两抽屉、逐页控件与出口已定义；低保真走查应检查推进权、未知呈现和跨页连续性。
- 运营：核心事件和口径已定义，selected/applied分开；暂无转化率或留存目标的研究基线。
- 隐私：最小上下文、访问隔离与删改影响已写；供应方和备份策略仍是公开上线前必需的部署审查。

下一步交接物：选择C01–C05默认值或修改值 → 根据P01–P09画线框 → 用同一真实案例走完整旅程与中断分支 → 将观察到的阻塞回写到PRD。不要仅根据文档长度判定开发已准备完毕。
